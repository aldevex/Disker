Codebase explanation (src/):

# Memory (mem/):
    - "darray.h": Dynamic array code.
    - "string.h": Dynamic string and string view code.
    - "mem.h": Includes the aforementioned files + some helper macros.
    - "core.h" & "core_imp.c": Core memory operations.

# Generic utility code (utils/):
    Contents are self explanatory.

# Production program resources (res/):
    Pictures and other resources for the production program to use.

# Disk and disk image focused code (disk/):
Disk and various image file formats (format/):
    - "format.h" & "format.c": Includes file format enum & format variant structure.
    - "raw.h": Code for raw disk images and real disks.
Disk schemes (scheme/):
    - "scheme.h": Includes scheme enum & total scheme data structure.
    - "mbr.h": MBR scheme structures.
    - "mbr_default.nasm": Default MBR sector assembly code.
    - "mbr_default.h": Embedded default MBR sector binary from assembly.
    - "gpt.h": GPT scheme structures.
File systems (fs/):
    - "fs.h": Includes file system enum & file system variant structure.
    - "fat.h": FAT structures.
Total disk info collection ("info.h" & "info.c"):
    Collection of all disk/image information to be used in program state.

# Core (core/):
Operation commands (cmds/):
TUI core (tui/):
    - "entry.c": Entry point. Also the exit point if exiting without critical errors.
    - "state.c": Core program state logic.
    - "parse.c": Command parsing implementation.
    - "cmds.h": Command structures and function declarations.
    - "error.c": TUI error printing implementation.
    - "tui.h": External declarations of TUI functions used outside their C files.



Program pipeline explanation:

# TUI pipeline:
    - parseCmd validates input grammar and validates input arguments
        according to expected numeric and textual values.
    - getRunCmds extracts commands one by one
        from direct arguments, a file, or the commandline,
        then validates them relative to the current program state,
        then apply the command to the program state and/or target disk state object,
        it actually saves the target disk object to the disk/image on "save" commands.
        The function must also open and lock input files
        directly after each command for a predictable successful save.
