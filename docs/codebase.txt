
Naming convention:

- Base types:                  lowercase suffixed by "_t".
- Types:                       PascalCase.
- Variables and functions:     camelCase.
- Constants:                   UPPER_SNAKE_CASE.

- Function-like macros:        camelCase
- Constant definition macros:  UPPER_SNAKE_CASE
- Files & directories:         lowercase, underscores ("_") for spacing.

- Program TUI output texts must be gramatically correct and with punctuation.



Data:

- Variables may not be defined globally.

- Variables may not be uninitialized.



Comments:

- Functions:
    1. Description of the function's task
        and final output (be it writing to a variable or to program environment (e.g. file, terminal))
    2. Details about unclear parameters (when the parameter's name doesn't fully explain how the argument is *read*)
    3. External writes (writing to data pointed-at by arguments)
    4. Return value (if not void)

- Structs, Enums, Macro-based Enums, & Typedefs:
    1. Description of the type's task
    2. Descriptions (written inside the type definition "{}") for each field's task and unclear usage

- Macros:
    1. Description of the macro's task
    2. Description of the macro's content



Textual signature (depending on available space):

- If 1-6 characters available: "D", "Dr", "Dkr", "Dskr", "Diskr", "Disker".

- If 7+ characters available: "Disker" padded by spaces, null terminators, or other characters,
                                depending on the medium's specification.

- In a UUID: "DSKR-DR-DR-DR-DISKER" encoded as UTF-8 bytes
            (44534B52-4452-4452-4452-4449534B4552)

- The signature must be inserted wherever possible to satisfy devs' ego.



Platform-dependancy:

- The core code (contents of "src/", excluding "src/base")
    must not contain platform-specific implementations,
    and must take processor endianness in consideration.

- The codebase primarily uses the UTF-8 encoding for textual data.



Program pipeline:

- The first (platform-specific) entry point (named "main" for a common platform environment)
    initializes base program state and environment, and calls the second entry point.

- The second (non-platform-specific) entry point (named "entry" in the current code)
    initializes core-logic program state and environment, and calls the core logic function.

- The core function (named "core" in the current code) and its segmented per-command functions
    run core program logic, and affect the state and environment depending on user input.
    They call functions in a modular manner depending on the given data
        (e.g. disk image file format, in-partition disk layouts).
    They validate user input relative to the program state and run part of the command
        only if the validation and the ran part of the command aren't layout-specific
        and would be the exact same for all layouts
        (e.g. closing an inexistent disk is invalid for any disk/image type)

- The program may not write directly to disk/image unless explicitly told to by user.



Codebase files outside "src/":

# "docs/": Internal disker developer documentation.
    - "codebase.txt": Codebase explanation.
    - "todo.txt": Todo list for the project.
    - "prototype.dr": Disker script prototype for target program functionality to implement.

# "specs/": Specifications for disk image file formats and file systems
            that don't have an official specification (or have an extremely bad one)
            on behalf of the original creators to aid them in their work.

# "precomp/": Pre-compilation code, must be compiled and ran before the main program code.
    - "embed.c": Embeds files into C headers in the main code.

# "prod/": Contains the program binary and the files it requires.
            Contents must be fetched via compile-time scripts, ***NOT manually edited***.
    - "data/": Program data files.
    - "docs/": User-targeted documentation.

# "res/": Files required by the program.
            Copied into "prod/" by compile-time scripts.
    - "windows.ico": Windows icon for the binary.
    - "windows.rc": Windows code referencing files to be embedded into the binary.
    - "default_mbr.nasm": NASM x86-16 assembly for the default value of a newly created MBR sector.
    - "config.ini": Disk-persistent variables used by the program itself at runtime.



Codebase files inside "src/" (main program code):

# "base/": Base and platform-specific definitions.
            The core base header is "core.h", other headers are for secondary base definitions.
            Implementation (".c") files must be prefixed by "impl_".

# "mem/": Memory managment.
    - "core.h" & "core_imp.c": Core internal memory definitions.
    - "darray.h": Dynamic array.
    - "string.h": Dynamic string and constant string view.
    - "mem.h": Interface header, includes the aforementioned files + some helper macros.

# "core/": Program core.
    - "utils/": Generic utility definitions.
    - "disk/": Disk-revolved and layout-specific definitions.
    - "tui/": Core logic for the TUI program.
    - "gui/": Core logic for the GUI program.
